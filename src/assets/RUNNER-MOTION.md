# Recorded running motion for RacePulsePH

This is a 2D projection of a real human running performance recorded by the Carnegie Mellon University Graphics Lab. The gait is not hand-invented or generated by an AI motion model. The character styling is separate from the motion data.

## Primary sources and reuse

- Database and terms: https://mocap.cs.cmu.edu/
- Clip listing: https://mocap.cs.cmu.edu/search.php?subjectnumber=09 (subject 9, motion 1, description `run`, 120 Hz).
- Skeleton: https://mocap.cs.cmu.edu/subjects/09/09.asf
- Recorded animation: https://mocap.cs.cmu.edu/subjects/09/09_01.amc
- Capture process: https://mocap.cs.cmu.edu/info.php

CMU's homepage permits use of the motion data, including within commercially sold products. It prohibits selling the motion data itself, including a converted version. The site's requested acknowledgement follows. Retain this attribution with the application source or third-party notices; it does not need to occupy the loading screen. The original source files and downloaded web pages are not included in this repository.

> The data used in this project was obtained from mocap.cs.cmu.edu. The database was created with funding from NSF EIA-0196217.

## Reproduction

From the repository root, run:

```sh
python -m pip install numpy
python scripts/derive-runner-motion.py --check
```

This optional authoring tool requires Python 3.10+ and NumPy. It downloads only the two source files listed above into a temporary directory, verifies their pinned SHA-256 hashes, derives the frames, and compares the result with `src/assets/runner-motion.ts`. Temporary source files are removed automatically. There are no downloads or Python dependencies in the application's runtime or normal build.

To regenerate `src/assets/runner-motion.ts`, omit `--check`. To reproduce without network access, supply `--source-dir /path/to/source-files`, containing `09.asf` and `09_01.amc`. To write a separate review copy, use `--output /path/to/runner-motion.ts`. Check mode compares the data payload and ignores the generated comment and file line endings.

Pinned original source hashes:

| File | SHA-256 |
| --- | --- |
| `09.asf` | `be10dbce393fd60a2d322410032d618757afcc5bb2f7a508d887c5b0213f1897` |
| `09_01.amc` | `02c94e8c2d4d2ff05f9a784f06403700c2c9d7caedd9bd92b50284d1a05f2bee` |

The script:

1. Reads the actual ASF bone axes, lengths, hierarchy, and AMC channel samples.
2. Performs forward kinematics using `parentRotation * C * motionRotation * inverse(C)` and the measured bone directions.
3. Projects the sagittal plane: world Z becomes screen X, negative world Y becomes screen Y. Only horizontal root travel is removed. The recorded vertical root bounce remains.
4. Selects a same-foot loop by minimizing pose and velocity differences over candidate full-stride periods.
5. Samples source frames 4 to 92 (1-based boundary frames) into 32 poses, excluding the duplicate end pose. The actual full-stride duration is 88 / 120 seconds, or **733.333 ms**.
6. Applies a smoothstep distribution of the small endpoint difference to close the loop. Maximum correction is **3.07 viewport units**; the source body height is normalized to approximately 132 units. This is loop cleanup, not a new gait.
7. Fits the whole cycle to a fixed `0 0 120 160` SVG viewBox, preserving measured limb ratios and vertical bounce, and rounds coordinates to 0.01 units.

## Export contract

`src/assets/runner-motion.ts` exports `runnerMotion`.

- `durationMs`: 733.333.
- `frames`: 32 arrays of 18 `[x,y]` joint positions.
- `joints`: corresponding names in order.
- `edges`: basic skeleton connections.
- Facing direction: right. Y increases downward.
- Ground reference: 148; feet correctly rise above this during the flight phase.
- Payload: JSON 8,709 bytes; gzip 3,656 bytes. No runtime 3D library.

Joints: `head`, `neck`, `chest`, `pelvis`, `leftShoulder`, `leftElbow`, `leftWrist`, `rightShoulder`, `rightElbow`, `rightWrist`, `leftHip`, `leftKnee`, `leftAnkle`, `leftToe`, `rightHip`, `rightKnee`, `rightAnkle`, `rightToe`.

The ASF head endpoint is near the crown. For a small stylized head ellipse, place its center between `head` and `neck`, not directly on `head`. Torso can use a thick chest-to-pelvis segment, but include pelvis-to-hip connections so there is no gap above the thighs. If using one hip origin instead, do not move the actual thigh endpoint more than necessary.

## Rendering guidance

The runtime uses `src/assets/runner-sprite.webp`: a transparent 8-by-4 atlas,
1920 by 1280 pixels, with 32 frames of 240 by 320 pixels. The atlas is 74,006
bytes. It preserves the sampled motion and adds a red singlet, race bib,
charcoal shorts, shoes, and rounded limbs. A single image is moved using discrete
transform offsets, while the outer crossing uses a smooth transform.

To regenerate this optional presentation asset after deriving the poses:

```sh
python -m pip install Pillow
python scripts/bake-runner-sprite.py
```

The sprite baker renders at a larger working resolution, downsamples the frames,
then uses a 64-color transparent palette and lossless WebP encoding. Neither
authoring script runs during normal application startup or the production build.
The pose TypeScript file is retained as authoring input; the loader imports only
the baked atlas.

The following notes also apply if a vector rendering of the source poses is needed.

Use filled rounded segments with a distinct torso and small head ellipse. Render the far limbs first and a little darker, then torso, then the near limbs; this prevents crossed arms and legs from becoming visually ambiguous. The joint trajectory is real, while red/white garment shapes can belong to RacePulsePH.

For each bone, derive angle with `atan2(y2-y1, x2-x1)` and length with `hypot(x2-x1, y2-y1)`. A constant horizontal capsule can use translate, rotate, and scaleX. Unwrap rotation angles across keyframes to prevent accidental full spins. Match the first keyframe again at 100% for a seamless 733.333ms loop. Linear interpolation between the 32 recorded samples works at this size; avoid per-bone easing, which changes timing between limbs. Pause the animation when the document is hidden and use a static natural contact pose for reduced motion.

The original recording includes asymmetric strides, shoulder motion, and natural forward lean; these are retained rather than mirrored into a generic cycle. The authoring script generates motion data only, without preview images or additional runtime assets.
